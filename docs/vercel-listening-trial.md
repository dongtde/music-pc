1. 两台设备分别打开前端的 `/space` 页面。
2. 打开一起听弹窗，在「连接设置」填写上面的后台连接地址，不要附加 `/health` 或其他路径。
3. 一台设备创建房间，另一台从房间列表或通过房间码加入。
4. 选择两台设备都能正常加载的在线歌曲，必要时点击「启用声音」。

前端可以继续运行在本机，后端地址通过弹窗填写即可。

## 结论

部署成功，短时间的房间发现、加入和共同控制可用。两轮云端检查均在约五分钟后出现连接问题，第二轮确认有客户端重连后找不到原房间。因此这版内存后端适合试用，不能作为持续多人听歌的可靠部署。

如果希望继续沿用现有内存实现，应使用支持公网访问的常驻单实例 Node.js 服务；也可以继续用 Vercel，但需要实现跨实例共享状态、消息广播和断线恢复。此次没有接入 Redis，也没有购买或创建付费服务器。

## 再次部署

Vercel CLI 已把 `backend/` 关联到上述项目。登录后可在该目录运行 `vercel deploy --prod`，不必部署前端。

本次工具使用的 CLI 登录配置位于项目忽略目录 `node_modules/.cache/vercel-config`，不是系统默认位置。复用该配置时为 CLI 指定 `--global-config`；也可以在普通终端运行 `vercel login` 使用系统默认登录位置。登录配置及 `backend/.env.local` 不应提交到 Git。
