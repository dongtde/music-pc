# 多人一起听

在 `/space` 通过地图或控制终端的「一起听」前往场景屏幕，直接创建或加入房间。屏幕位于唱片档案区靠近入口的展位。旁边原来的「唱片 03」已改为「歌曲搜索」：小屏直接展示搜索框、历史记录和热门搜索，历史与热搜数据和 2D 共用；点击输入框、历史词或热搜即可操作，无需经过介绍页。搜索结果、滚动加载、收藏、单曲加入和全部加入播放列表都在这块小屏内操作；Esc 或点击屏幕外退出操作后，屏幕仍展示当前页面并保留搜索结果。点击一起听屏幕空白处、创建或加入成功都不会展开大厅面板。默认每房间最多 10 人（包含房主），所有成员都能添加歌曲、切歌、播放、暂停、调整进度和播放模式，音量各自调整。房主保留结束房间的权限。

## 前后端结构

项目根目录是 Vue/Electron 前端；`backend/` 是独立的 Node.js 后端，拥有自己的 `package.json`、锁文件、环境配置和测试。可以把 `backend/` 单独复制到另一台服务器部署。

前端只包含 Socket.IO 客户端，后端单独安装 Socket.IO 服务端。两端通过网络连接，不导入对方的业务代码；原来内嵌在 Vite 中的房间服务已移除。Electron 主进程属于桌面客户端，仍放在前端项目中。

## 自动查找房间

靠近「一起听」屏幕会自动查询当前连接地址上的房间。列表展示房主、人数和当前歌曲，每 5 秒更新一次。筛选栏右侧依次为创建房间（房子右上角带小加号）、房间码加入（钥匙）、搜索和刷新图标。右上角设置图标可修改昵称和连接地址；点击列表中的房间即可加入，钥匙图标可输入房间码或粘贴完整邀请。

搜索、房间码、设置和邀请输入层都嵌在这块 3D 小屏幕内，随屏幕的位置、缩放和透视对齐，只遮罩屏幕内部，不打开浏览器顶层弹窗。弹窗仅保留主标题，支持中文输入、粘贴、Enter 提交、Tab 切换和 Esc 关闭；校验错误也显示在屏幕内。输入期间停止角色移动，场景与音乐继续运行。

列表展示同一个一起听服务中的房间概览，多个前端使用同一后端时会看到同一份列表。满员和房主重连中的房间会标记为不可加入，已经结束的房间会在更新时移除。点击加入后，服务器会再次检查房间和剩余名额。

查找期间可继续个人播放。离开屏幕附近、加入成功或页面进入后台后，停止查询；修改连接地址时会取消旧请求并重新查找。列表接口不可用时可检查连接设置或再次刷新，房间码入口仍可使用。

## 同一局域网

首次在项目根目录安装两端依赖：

```sh
npm ci
npm --prefix backend ci
```

随后打开两个终端，分别运行：

```sh
npm --prefix backend run dev
```

```sh
npm run dev
```

1. 后端默认运行在 `3030` 端口；前端通常运行在 `5173`，以实际输出为准。前端通过开发代理转发房间请求，代理目标默认是 `http://127.0.0.1:3030`。
2. 各台设备连接同一个 Wi-Fi，访问前端的 Network 地址，例如 `http://192.168.1.10:5173/space`。
3. 房主在控制终端创建空房间，点击「复制邀请」，进入后再选择在线歌曲。
4. 好友在各自设备上选择「加入房间」，点击自动查找到的房间，也可以粘贴完整邀请或单独输入房间码。所有成员的连接地址需要通向同一个后端。

从 `localhost` 创建时，邀请会尝试填入后端的局域网地址，端口通常是 `3030`。电脑有多个网络时请核对地址。Windows 防火墙需要允许所使用的前端和后端端口；直接粘贴带后端地址的邀请时，另一台设备会直连后端。

正式环境执行根目录的 `npm run build`，将生成的服务器部署包上传并按 [宝塔部署指南](baota-deployment.md) 配置 Nginx 和后台进程。

## Electron 或独立部署

仅打包后端时，在 `backend/` 执行 `npm run build`，上传 `backend/release/` 中的压缩包。服务器解压后在后台目录执行 `npm ci --omit=dev` 和 `npm start`。详细说明见 [后端 README](../backend/README.md)。

前端配置放在项目根目录 `.env` / `.env.local`：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `LISTENING_API_TARGET` | `http://127.0.0.1:3030` | Vite 开发和预览代理使用的后端地址，不进入浏览器构建 |
| `VITE_LISTENING_SERVER_URL` | 空 | 浏览器/Electron 直接连接的后端地址，在构建前配置 |

后端配置单独放在 `backend/.env`，可从该目录 `.env.example` 复制。后端支持 `LISTENING_PORT`、`LISTENING_HOST`、`LISTENING_ROOM_CAPACITY`、`LISTENING_ALLOWED_ORIGINS` 和 `LISTENING_PUBLIC_URL`。后者用于让复制的邀请包含正确的公网后端地址。

人数上限默认 `LISTENING_ROOM_CAPACITY=10`，允许 2–50 的整数，包含房主以及仍在 30 秒重连保留期内的成员。修改后重启后端即可，前端会显示服务器返回的人数上限；重启也会结束已有房间。房间状态仍保存在单个进程中，部署时保持单实例运行。

独立服务提供房间目录、房间通信与 `/health`，网页和音乐接口仍使用项目现有的部署。跨网络使用时，为后端配置公网域名与 HTTPS，转发 `/listening-room/rooms` 的 HTTP 请求及 `/listening-room/socket.io/` 的 WebSocket Upgrade 请求；可以统一代理整个 `/listening-room/`。前端可设置 `VITE_LISTENING_SERVER_URL` 直连该域名，或在前端站点配置同域反向代理；生产静态站点不会读取 Vite 的开发代理配置。HTTPS 网页应连接 HTTPS 后端。

## 同步规则

- 服务器维护唯一的曲目、队列、播放进度和时钟基准。切歌时等待所有在线成员加载音源，再按统一时间开始播放；加载失败或超时会提示重新同步或换歌。
- 新房间的播放列表为空，不导入房主的个人列表。创建或加入成功后保留个人列表、当前歌曲、进度和播放模式；房间中的变化不会写入个人播放缓存。
- 小屏幕选歌、放入唱片和曲库“全部加入”只将歌曲追加到终端队尾，不打断当前播放或取消暂停；重复歌曲保留原位置。歌曲结束后按当前播放模式继续播放队列。
- 空房间添加第一首歌后也保持待播，点击终端播放按钮即可开始队首歌曲。终端歌曲行的双击和封面播放按钮仍可主动切歌。
- 客户端连接时和每 30 秒校准时钟，每 2 秒拉取完整状态进行纠偏。延迟较大的成员加载完成后追上当前进度。
- 新切歌会使旧加载结果和过期的进度、上下首操作失效；指令编号按成员去重。拖动进度会合并密集请求。
- 所有成员都能控制播放。服务器按收到指令的顺序更新并广播状态；同时加歌会合并到共享队列。队列最多 200 首，满额后拒绝新增，不会挤掉已有歌曲。替换或清空队列时校验队列版本，遇到冲突会提示查看最新队列后重试。
- 自动连播由服务器决定，成员的本地歌曲结束事件不会独立触发下一首。
- 房主掉线后房间暂停，保留 30 秒重连窗口；超时或房主主动结束时关闭房间。好友掉线不暂停房主，位置保留 30 秒。
- 刷新页面可通过当前标签页的临时会话恢复房间。切换 2D/3D 不会关闭连接。
- 在音乐馆内主动创建或加入房间时，保留当前位置和朝向，并立即同步给房间成员；刷新页面和断线重连仍从服务器保存的位置恢复。
- 主动退出、房间结束或离线退出时，恢复进入前的个人列表、当前歌曲、进度和播放模式，并保持暂停。短暂断线重连仍留在共享列表，不会提前恢复个人列表。刷新页面后恢复房间，也不会覆盖个人缓存。
- 房间操作保留在场景屏幕上：房间码和复制位于标题旁，人数和退出位于右上角；启用声音、重新加载和重新同步仅在需要时显示。房主头像带皇冠角标，选歌和播放控制使用控制终端。

## 第一版边界

房间只保存在服务内存中，服务重启后需重新建房。音乐不经过房间服务器转发，各端通过自己的音乐账号获取同一曲目的音源；播放地址、Cookie 和账号凭证不会广播给好友。本地文件暂不参与一起听，无法加载或时长不一致的音源会显示错误。

目前提供邀请码、多人播放同步和房间内 3D 角色；好友关系、语音和跨服务器房间存储留待后续版本。实际听感还受网络、音源缓冲和设备音频输出延迟影响。

## Fantasy Queen 人物与实时移动

`/space` 中自己和所有好友统一使用 `public/models/Fantasy_Queen_Walk.glb`，包含修正摆臂后的循环行走以及站立、坐姿和跳跃姿态。旧的五款 Q 版角色选择入口已移除。每个人保留独立昵称、位置、骨骼和动画状态；纹理、材质与网格在同一场景内共享，模型只加载一次。

人物外观不再取决于服务器保存的旧角色编号，因此此项模型替换只需更新前端。已有成员身份、座位占用和移动消息格式保持兼容。

人物 GLB 使用 Meshopt 压缩和内嵌 4K KTX2 纹理，约 3.30 MB。解码器随前端 `assets/` 一起打包；更新模型时需要一并部署前端代码和资源，不能只替换旧版本站点的 GLB。压缩来源与参数见 [模型说明](../public/models/README.md)。

- 默认第三人称显示自己的身体；WASD 移动、Shift 加速、空格跳跃、V 切换第一/第三人称。也可以点击左下角按钮切换视角和跳跃。坐着时空格先起身；点击椅子或地图座位即可落座。
- 创建或加入一起听房间后，所有处于 3D 页面的在线成员都有独立角色和昵称。移动、朝向、行走/跑步、跳跃高度和坐姿通过现有 WebSocket 同步；远端平滑追随最新位置。
- 服务端每 50 毫秒最多广播一份紧凑位置状态，移动包与歌曲队列、播放版本分开。校验成员身份、房间范围、角色选项、有限坐标和递增序号，每个连接最多接收 25 个移动包/秒；离线移动包不积压重发。
- 服务端决定座位占用，同一座位一次只允许一人。起身、退出 3D、断线或离开房间会释放座位；断线角色立即隐藏，重连恢复原成员身份并回到可站立的位置。
- 切换 2D 会隐藏自己的角色，但不会退出一起听。只有同一个房间的成员能收到彼此的角色状态。

上线时需要同时更新前端和 `backend` 并重启后端。`npm run build` 的宝塔包和后台独立构建均包含 `src/presence.js`。继续使用现有 `/listening-room/` 反向代理，不需要额外端口、Redis 或模型服务。

当前采用客户端移动、服务器校验并转发的轻量方案，非竞技游戏的服务器物理模拟；人物之间可以穿行，家具碰撞沿用本地场景规则。坐姿为关节动画，不包含布料或物理布娃娃。

## 验证

部署后先访问 `/health` 确认服务正常，再使用两台设备验证创建、加入、共同加歌和控制，并持续试听至少 10 分钟。
