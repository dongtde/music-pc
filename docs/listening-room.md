# 多人一起听

在 `/space` 走到音乐控制终端，顶部有「创建房间」和「加入房间」。默认每房间最多 10 人（包含房主），所有成员都能添加歌曲、切歌、播放、暂停、调整进度和播放模式，音量各自调整。房主保留结束房间的权限。

## 前后端结构

项目根目录是 Vue/Electron 前端；`backend/` 是独立的 Node.js 后端，拥有自己的 `package.json`、锁文件、环境配置和测试。可以把 `backend/` 单独复制到另一台服务器部署。

前端只包含 Socket.IO 客户端，后端单独安装 Socket.IO 服务端。两端通过网络连接，不导入对方的业务代码；原来内嵌在 Vite 中的房间服务已移除。Electron 主进程属于桌面客户端，仍放在前端项目中。

## 自动查找房间

打开控制终端的「加入房间」，会自动查询当前连接地址上的房间。列表展示房主、房间码、人数和当前歌曲，每 5 秒更新一次，也可以点击「刷新」。填写昵称后，点击列表中的房间即可加入；下方仍可输入房间码或粘贴完整邀请。

列表展示同一个一起听服务中的房间概览，多个前端使用同一后端时会看到同一份列表。满员和房主重连中的房间会标记为不可加入，已经结束的房间会在更新时移除。点击加入后，服务器会再次检查房间和剩余名额。

查找期间可继续个人播放。关闭面板、切换到创建房间、加入成功或页面进入后台后，停止查询；修改连接地址时会取消旧请求并重新查找。列表接口不可用时会显示原因，房间码入口仍可使用。

## 同一局域网

首次在项目根目录安装两端依赖：

```sh
npm ci
npm --prefix backend ci
```

随后打开两个终端，分别运行：

```sh
npm --prefix backend run dev
```

```sh
npm run dev
```

1. 后端默认运行在 `3030` 端口；前端通常运行在 `5173`，以实际输出为准。前端通过开发代理转发房间请求，代理目标默认是 `http://127.0.0.1:3030`。
2. 各台设备连接同一个 Wi-Fi，访问前端的 Network 地址，例如 `http://192.168.1.10:5173/space`。
3. 房主选择在线歌曲，在控制终端创建房间，点击「复制邀请」。
4. 好友在各自设备上选择「加入房间」，点击自动查找到的房间，也可以粘贴完整邀请或单独输入房间码。所有成员的连接地址需要通向同一个后端。

从 `localhost` 创建时，邀请会尝试填入后端的局域网地址，端口通常是 `3030`。电脑有多个网络时请核对地址。Windows 防火墙需要允许所使用的前端和后端端口；直接粘贴带后端地址的邀请时，另一台设备会直连后端。

正式环境执行根目录的 `npm run build`，将生成的服务器部署包上传并按 [宝塔部署指南](baota-deployment.md) 配置 Nginx 和后台进程。

## Electron 或独立部署

仅打包后端时，在 `backend/` 执行 `npm run build`，上传 `backend/release/` 中的压缩包。服务器解压后在后台目录执行 `npm ci --omit=dev` 和 `npm start`。详细说明见 [后端 README](../backend/README.md)。

前端配置放在项目根目录 `.env` / `.env.local`：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `LISTENING_API_TARGET` | `http://127.0.0.1:3030` | Vite 开发和预览代理使用的后端地址，不进入浏览器构建 |
| `VITE_LISTENING_SERVER_URL` | 空 | 浏览器/Electron 直接连接的后端地址，在构建前配置 |

后端配置单独放在 `backend/.env`，可从该目录 `.env.example` 复制。后端支持 `LISTENING_PORT`、`LISTENING_HOST`、`LISTENING_ROOM_CAPACITY`、`LISTENING_ALLOWED_ORIGINS` 和 `LISTENING_PUBLIC_URL`。后者用于让复制的邀请包含正确的公网后端地址。

人数上限默认 `LISTENING_ROOM_CAPACITY=10`，允许 2–50 的整数，包含房主以及仍在 30 秒重连保留期内的成员。修改后重启后端即可，前端会显示服务器返回的人数上限；重启也会结束已有房间。房间状态仍保存在单个进程中，部署时保持单实例运行。

独立服务提供房间目录、房间通信与 `/health`，网页和音乐接口仍使用项目现有的部署。跨网络使用时，为后端配置公网域名与 HTTPS，转发 `/listening-room/rooms` 的 HTTP 请求及 `/listening-room/socket.io/` 的 WebSocket Upgrade 请求；可以统一代理整个 `/listening-room/`。前端可设置 `VITE_LISTENING_SERVER_URL` 直连该域名，或在前端站点配置同域反向代理；生产静态站点不会读取 Vite 的开发代理配置。HTTPS 网页应连接 HTTPS 后端。

## 同步规则

- 服务器维护唯一的曲目、队列、播放进度和时钟基准。切歌时等待所有在线成员加载音源，再按统一时间开始播放；加载失败或超时会提示重新同步或换歌。
- 客户端连接时和每 30 秒校准时钟，每 2 秒拉取完整状态进行纠偏。延迟较大的成员加载完成后追上当前进度。
- 新切歌会使旧加载结果和过期的进度、上下首操作失效；指令编号按成员去重。拖动进度会合并密集请求。
- 所有成员都能控制播放。服务器按收到指令的顺序更新并广播状态；同时加歌会合并到共享队列。队列最多 200 首，满额后拒绝新增，不会挤掉已有歌曲。替换或清空队列时校验队列版本，遇到冲突会提示查看最新队列后重试。
- 自动连播由服务器决定，成员的本地歌曲结束事件不会独立触发下一首。
- 房主掉线后房间暂停，保留 30 秒重连窗口；超时或房主主动结束时关闭房间。好友掉线不暂停房主，位置保留 30 秒。
- 刷新页面可通过当前标签页的临时会话恢复房间。切换 2D/3D 不会关闭连接。
- 退出后暂停当前歌曲、解除房间控制，保留歌曲与队列供个人继续播放。
- 浏览器阻止自动播放时，房间面板会显示「启用声音」。加载失败可重试，任何成员都可点击「重新同步」或换歌。

## 第一版边界

房间只保存在服务内存中，服务重启后需重新建房。音乐不经过房间服务器转发，各端通过自己的音乐账号获取同一曲目的音源；播放地址、Cookie 和账号凭证不会广播给好友。本地文件暂不参与一起听，无法加载或时长不一致的音源会显示错误。

目前提供邀请码和多人播放同步；好友关系、语音、远端 3D 人物和跨服务器房间存储留待后续版本。实际听感还受网络、音源缓冲和设备音频输出延迟影响。

## 验证

后端自动化用例保留在 `backend/test/`，通过 Node.js 测试运行器执行。部署后使用两台设备验证创建、加入、共同加歌和控制，并持续试听至少 10 分钟。
